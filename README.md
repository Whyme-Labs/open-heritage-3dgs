# Open heritage 3DGS prototype

Self-hosted WebGPU-first 3D Gaussian splat prototype built on **Vite** and deployed to **Cloudflare Workers**, with large scene binaries served from an **R2 bucket** through a Worker route that supports `HEAD` and byte-range requests. The client prefers WebGPU, falls back to WebGL2, supports local PLY and SOG files, adds mobile controls, and keeps the camera inside a configurable boundary.

## Architecture

```text
index.html + src/app.js     Vite client bundle (scene list, quality/renderer UI, iframe bridge)
public/viewer/              Prebuilt SuperSplat viewer (generated by scripts/build-viewer.mjs)
public/scenes.json          Scene manifest
public/boundaries/*.json    Camera geofence definitions (small, static)
worker/index.ts             Worker: serves /scenes/* from R2 (Range + HEAD), rest goes to static assets
wrangler.jsonc              Workers config: SCENES R2 binding, run_worker_first for /scenes/*
scenes/                     Local source of truth for scene binaries; synced into R2, never bundled
```

Why this layout:

- Workers static assets cap files at 25 MiB, so 100 MB+ PLY/SOG binaries cannot ship as assets.
- The `SCENES` R2 binding has no per-object size limit and supports range reads; `worker/index.ts` translates HTTP `Range` headers to R2 range gets so the viewer can stream large splat files exactly like the previous Node server did.
- URL path equals R2 key (`/scenes/pantheon-interior.ply` -> key `scenes/pantheon-interior.ply`), so adding asset classes later only requires widening `run_worker_first`.

## Quick start (local dev)

```bash
./setup.sh            # install deps + build viewer + verify
npm run sync:r2       # seed the local simulated R2 bucket from scenes/
npm run dev           # http://localhost:5173
```

The dev server runs the real Worker with local R2 emulation via `@cloudflare/vite-plugin`. Do not open `index.html` through `file://`; WebGPU setup, module loading, and range streaming require the dev server.

## Deploy to Cloudflare

```bash
npx wrangler r2 bucket create open-heritage-scenes   # once per account
npm run sync:r2:remote                               # upload scenes/ to real R2
npm run deploy                                       # build + wrangler deploy
```

`npm run deploy` ships the Worker plus static assets in one unit; scene binaries are pulled from R2 at request time. Re-run `sync:r2:remote` whenever you add or regenerate files under `scenes/` (for example after `prepare:scene`).

This device has access to multiple Cloudflare accounts. Export the target account before wrangler commands:

```bash
export CLOUDFLARE_ACCOUNT_ID=1e0170aaabc90ecf5f466128d1f0466a   # Swmengappdev@gmail.com's Account
```

Live deployment: `https://open-heritage-3dgs.swmengappdev.workers.dev`

## What changed in this revision

- Migrated from the custom Node HTTP server (`scripts/serve.mjs`, removed) to Vite 8 + `@cloudflare/vite-plugin` + Cloudflare Workers.
- Scene binaries now live in an R2 bucket (`SCENES` binding); `worker/index.ts` serves `/scenes/*` with `HEAD`, byte ranges, ETags, and 416 handling.
- The viewer is still built locally from the official `@playcanvas/supersplat-viewer`, now into `public/viewer/`.
- WebGPU is requested by default. WebGL2 remains available through the Renderer selector.
- SOG is preferred over PLY because it is much smaller for browser delivery.
- Mobile has a movement joystick, look pad, mode button, speed modes, reset, fullscreen, vertical movement, and jump.
- The joystick feeds the viewer's native keyboard input path. If collision is present, walk-mode movement uses that collision.
- Every scene has an automatic world-space geofence. Manual box and polygon boundaries are supported.
- The downloader now skips existing files and continues after one scene fails.

```

2. Attempt Saka Shrine.

saka-shrine.sog

saka-shrine.ply
```

Keep the real extension. Do not rename a SOG file to PLY.

## Convert Pantheon PLY to SOG

The PLY works directly. SOG is better for a web prototype.

First install and build:

```bash
./setup.sh
```

Convert without collision:

```bash
SKIP_COLLISION=1 npm run prepare:scene -- pantheon-interior interior
```

The output is:

```text
scenes/pantheon-interior.sog
```

The app automatically chooses SOG before PLY. After generating new files under `scenes/`, run `npm run sync:r2` (or `sync:r2:remote`) so the Worker can serve them.

SOG conversion uses WebGPU when available and retries on CPU if GPU compression fails:

```bash
FORCE_CPU=1 SKIP_COLLISION=1 npm run prepare:scene -- pantheon-interior interior
```

## Generate collision for walls and floors

The camera boundary is a geofence. It prevents leaving the overall scene volume, but it does not infer every wall, floor, doorway, stair, or obstacle.

Collision generation adds that second layer. Current SplatTransform collision generation requires a working WebGPU or Vulkan device.

For Pantheon, open the viewer and press `XYZ` to copy a camera coordinate from a valid point inside the navigable space. Then run:

```bash
SEED_POS="x,y,z" npm run prepare:scene -- pantheon-interior interior
```

This generates:

```text
scenes/pantheon-interior.voxel.json
scenes/pantheon-interior.voxel.bin
scenes/pantheon-interior.collision.glb
```

The application detects the collision file on the next reload and passes it to the viewer.

For an outdoor scene:

```bash
npm run prepare:scene -- christchurch-castle exterior
```

If collision generation fails, the SOG output remains usable and the camera geofence remains active.

## Boundary configuration

Each scene has a file under `boundaries/`.

Automatic mode:

```json
{
  "version": 1,
  "enabled": true,
  "type": "auto",
  "padding": 0.06,
  "verticalPadding": 0.1,
  "orbitPadding": 0.55,
  "maxOrbitDistanceScale": 1.8
}
```

The viewer derives a world-space bounding box from the loaded splat. Positive `padding` and `verticalPadding` inset the fly/walk box so the camera stops before the raw splat edge. Orbit mode gets a separate expanded box because an orbiting camera normally sits outside the visible object.

For an explicit box:

```json
{
  "version": 1,
  "enabled": true,
  "type": "box",
  "min": [-8, -1, -10],
  "max": [9, 8, 11],
  "padding": 0.02,
  "verticalPadding": 0.02,
  "orbitPadding": 0.5
}
```

For a walkable XZ polygon:

```json
{
  "version": 1,
  "enabled": true,
  "type": "polygon",
  "points": [
    [-4, -6],
    [5, -6],
    [7, 2],
    [2, 8],
    [-5, 4]
  ],
  "minY": 0.2,
  "maxY": 4.0,
  "padding": 0.02,
  "verticalPadding": 0.02,
  "orbitPadding": 0.5
}
```

Polygon coordinates use the same world coordinate system displayed by the `XYZ` button.

## Performance controls

The main page has four quality choices:

- Auto uses a lower splat budget on mobile.
- Low uses a small budget and disables post effects.
- Balanced is suitable for most laptops and recent phones.
- High raises the budget for larger scenes.

The viewer also:

- caps mobile render resolution,
- switches to on-demand rendering after loading,
- lowers streamed detail behind the camera,
- uses GPU sorting under WebGPU,
- falls back to WebGL2 if WebGPU is unavailable.

A 500,000-splat PLY is already below the default desktop budget. SOG still reduces network transfer and parsing overhead.

## Mobile controls

- Left circle: move.
- Right pad: look.
- Mode: orbit and fly, plus walk only when the collision asset loads and the viewer marks the scene walkable.
- Speed: slow, normal, fast.
- Up: rise in fly mode, jump in walk mode.
- Down: descend in fly mode.
- Reset: return to the initial camera.
- Full: fullscreen.
- XYZ: copy the current camera position.

The rest of the canvas keeps the official viewer's touch gestures.

## File selection order

For each scene, the app checks:

1. `scenes/<slug>.sog`
2. `scenes/<slug>.compressed.ply`
3. `scenes/<slug>.ply`

For collision, it checks:

1. `scenes/<slug>.collision.glb`
2. `scenes/<slug>.voxel.json`
